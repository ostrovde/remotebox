A Windows VPS for 24/7 automation, step by step

A Windows box that runs your job while you watch it will stop the moment you close the window. Making it survive the night is four settings, and all four are about sessions and updates.

1. Understand what disconnect does

Closing an RDP window does not shut down the machine, but it does end your session. Anything that needs an interactive desktop — a browser with a visible window, a GUI application, a macro recorder — dies with it unless you configure otherwise. Headless scripts and services survive because they never needed the session.

Consequence: decide early whether your tool is headless. If it is not, either keep a session alive deliberately or run it as a service with a desktop session configured — both are extra work, and both are avoidable if the tool has a headless mode.

2. Autostart that survives a reboot

Hosts reboot for maintenance. Set up for it:

  • Task Scheduler with the trigger At startup and the option Run whether user is logged on or not is the most reliable path for scripts.
  • For interactive tools, tick Run only when user is logged on and ensure the account logs in automatically, or use a service wrapper.
  • Avoid Startup folder shortcuts — they are the least reliable of the options.
  • Have the job write a heartbeat file with a timestamp every minute. It is the cheapest way to answer “did it survive the night”.

3. Take control of updates

The default Windows update behaviour will restart your machine at the exact moment your job is mid-run. Configure active hours, set updates to download but not auto-restart, and restart on your schedule after the job finishes.

Also confirm what the host patches. Some providers manage updates themselves and will reboot your box on their own cadence regardless of your settings.

4. Make failures loud

An unattended job that silently stops is worse than one that crashes, because you find out days later from the data. Add:

  • A log file that is appended to, not overwritten, and rotated.
  • A heartbeat check from outside the box — if the file stops updating, you get a message.
  • Exit codes written down. A job that exits 0 after doing nothing looks identical to success.

The setup sequence that works

  1. Create a dedicated non-admin user for the job (see the RDP security checklist).
  2. Install dependencies and pin their versions.
  3. Run the job once manually, end to end, and confirm output.
  4. Register the Task Scheduler entry with At startup + run whether logged on or not.
  5. Reboot the machine and verify the job starts on its own.
  6. Leave it overnight. Check the heartbeat, not your memory of what you configured.

Step five is the one people skip, and it is the only one that proves anything. Hosts that let you reboot and reinstall quickly make this iteration cheap — with managed RDP plans the image is the provider's responsibility, which removes a whole class of “it worked yesterday” failures.

Short version

  • Disconnecting ends your session, not the machine — interactive tools die with it.
  • Task Scheduler with “run whether logged on or not” beats every other autostart method.
  • Stop Windows from rebooting mid-job; check whether the host reboots you anyway.
  • Add a heartbeat file, then reboot and verify before trusting it overnight.
